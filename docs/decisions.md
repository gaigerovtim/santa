# Решения по ТЗ версии 1

Уточнения к `docs/spec-v1-site.md`, принятые 17.11.2026.

1. **Перегенерация превью** заново делает только `frameA`. `frameB` генерируется после оплаты, в задаче очереди `video`. Поэтому превью-задача выполняет шаги `prepareRoomPhoto` и `editFrame frameA`, а видео-задача — `frameB`, `clip`, `final`.
2. **Ручное одобрение.** `MANUAL_APPROVAL` в `.env` задаёт начальное значение. Переключатель в админке сохраняет новое значение в базу (таблица настроек), и дальше действует оно. В e2e-тестах одобрение выключено.
3. **Реквизиты, контакты, адрес отправителя** пока заглушки, собранные в `config/site.ts` (`MAIL_FROM` по-прежнему берётся из `.env`).
4. **Брошенные загрузки.** Фото без заказа старше 24 часов удаляет ежедневная задача очистки.
5. **Файлы-заглушки** (`frame-example.jpg`, `clip.mp4`, `silhouette.png`, `steps-bells.wav`) генерируются временно, пока нет настоящих. Замена — положить свой файл с тем же именем.
6. **`spec-stage1.md`** пока нет; промпты в `config/prompts.ts` — черновые, заменяются, когда файл появится.
7. **Хранилище локально — RustFS вместо MinIO.** Образы MinIO больше не публикуются в Docker Hub и quay.io. RustFS (Apache-2.0) говорит на том же S3 API, код работает с ним через `@aws-sdk/client-s3` так же, как с Yandex Object Storage. Сервис в compose называется `s3`.
8. **Дополнительные таблицы:** `payments` (платежи mock-провайдера), `uploads` (учёт загрузок для очистки брошенных), `settings` (ручное одобрение). Дополнительное поле заказа `last_error` — для карточки в админке.
9. **Скорость главной.** Итог этапа 8 (Lighthouse, мобильный, продакшен-сборка в Docker, 5 замеров): Performance — медиана 92 (96 / 82 / 93 / 82 / 92), Accessibility, Best Practices, SEO — 100, CLS 0. Разброс — от нагрузки ноутбука Docker-стеком; на отдельном сервере стоит перемерить. Сделано: один постер первого экрана с `fetchPriority="high"`, предзагружается только шрифт заголовков, JetBrains Mono — вариативный, главная собирается статически.
10. **Загрузка фото.** Браузер переводит HEIC в JPG, поворачивает по EXIF, уменьшает до 2560 px и перекодирует в JPEG — метаданные (включая геолокацию) удаляются до загрузки. Загрузка — подписанной POST-формой (presigned POST): лимит 15 МБ и тип файла проверяет само хранилище. Ссылок на загрузку — не больше 30 в час с IP (счётчик в Redis). Превью в час с IP считаются по истории статусов (переходы в `preview_generating`), поэтому перегенерации тоже входят в лимит 5.
11. **Превью.** prepareRoomPhoto приводит фото к 1920×1080: горизонтальное обрезается по центру, вертикальное вписывается целиком на размытый фон (ёлка не обрезается). Превью — 1280 px с диагональной сеткой «ПРЕВЬЮ · ДЕД МОРОЗ». Почта на странице заказа показывается частично (`an••@example.ru`): ссылкой могут поделиться. `attempts` считает все вызовы провайдеров, включая неудачные; `cost_usd` — только успешные.
12. **Оплата.** Webhook не доверяет телу уведомления: статус, сумма и заказ берутся из `verifyPayment` (так ЮKassa и рекомендует). Сумма у провайдера сверяется с `amount_rub` заказа. Переход в `paid` — условный (`allowSame`), задача видео — с фиксированным `jobId`, поэтому повтор ничего не меняет. Если оплата пришла для заказа, который уже не ждёт её (например, истёк), статус не меняется, ошибка пишется в `last_error` для админки. Адрес возврата с `/mock-pay` вычисляется на сервере по заказу — без открытого редиректа. В Docker сайт работает в `NODE_ENV=production`, заглушки включены флагом `ENABLE_MOCKS=true` из compose.
13. **Видео и письма.** Постобработка — ffmpeg в образе воркера: чёрно-белый кадр, зерно, виньетка, таймкод от 31.12.2026 03:14:07, мигающая метка REC, подпись «КАМЕРА 2 · ГОСТИНАЯ», звук `assets/sfx/steps-bells.wav` (пока синтезированная заглушка — заменить звуком с коммерческой лицензией). Шрифт таймкода — `assets/fonts/JetBrainsMono-Regular.ttf`, если положить файл; иначе DejaVu Sans Mono из образа. Письмо «Заказ оплачен» уходит только при первом переходе в `paid`; ошибка почты не ломает оплату и конвейер. На странице с готовым видео рамка без своего REC/таймкода — они уже вшиты в ролик. Застрявшие оплаченные заказы ставятся в очередь заново: `docker compose exec worker npx tsx scripts/requeue-paid.ts`.
14. **Админка.** Сессия — подписанная HMAC-SHA256 cookie `admin_session` (httpOnly, SameSite=Strict, 12 часов); админка выключена, если пуст `ADMIN_PASSWORD` или `SESSION_SECRET` короче 32 символов. Пароль сравнивается за постоянное время; входов — не больше 10 за 15 минут с IP. POST-запросы `/api/admin/*` принимаются только с заголовком Origin своего сайта (защита от CSRF). Набор доступных действий зависит от статуса и факта оплаты (`availableActions`): одобрить — review; перегенерировать — видео для оплаченных, кадр для неоплаченных; вернуть деньги — только оплаченные; письмо повторно — по статусу (готово / оплачено / задерживаемся), повторная отправка пишется в историю. Выручка за день — оплаты по московскому времени без возвращённых заказов.
15. **Этап 8: очистка, защита, тесты.** Очистка — задача BullMQ по расписанию (04:00 МСК), решение «что удалить» — чистая функция `planCleanup`; возвращённые без доставки заказы чистятся через 30 дней. IP для лимитов берётся из `X-Real-IP`, а если его нет — из **последнего** адреса `X-Forwarded-For` (его дописывает наш прокси; первые адреса клиент может подставить сам). Заглушки читают задержки и вероятность сбоя на лету из хеша Redis `mock:config` — только там, где разрешены заглушки; так e2e и нагрузочный тест управляют ими без перезапуска воркера. Форма `/create` подхватывает файл, выбранный до «оживления» страницы (раньше такой выбор терялся). Несуществующий заказ и вход в админку без сессии отвечают HTTP 200 с потоковым `notFound`/`redirect` — так работает Next.js 16 с Cache Components; содержимое — страница 404 / перенаправление, данные не утекают.
